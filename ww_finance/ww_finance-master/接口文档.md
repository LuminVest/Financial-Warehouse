# 旺旺银行托管平台 接口文档

> **面向对象**：商户端（旺旺信贷业务平台）开发人员
>
> **银行端服务**：`ww_bank` 项目，默认端口 `9090`
>
> **Base URL**：`http://localhost:9090`

---

## 一、通用约定

### 1.1 请求方式
- **全部接口**：`POST`
- **Content-Type**：`application/x-www-form-urlencoded`
- **参数格式**：`key=value&key=value`，所有值均为字符串

### 1.2 签名规则（强制）

所有请求必须带 `sign` 参数，算法如下：

1. 参与签名的参数（**排除 `sign` 字段本身**）
2. 参数按 **key 字典序升序** 排列
3. 按 `value1|value2|value3|...|valueN` 用 `|` 拼接（只用 value，不用 key）
4. 末尾再拼接一个 `|`，然后拼接签名密钥 `9876543210`
5. 整串做 **MD5**（32 位小写）

**伪代码**：
```
sortedParams = sortByKey(params)
str = ""
for p in sortedParams:
    str += p.value + "|"
str += "9876543210"
sign = MD5(str).toLowerCase()
```

**示例**（绑定接口，参数 agentId=1001, agentUserId=user001, ...）：
```
签名前明文：
1001|user001|6225000000000001|test@test.com|110101199001011234|13800138000|http://localhost:5173/notify|123456|张三|http://localhost:5173/return|0|1693520000000|9876543210

sign（MD5）：
a1b2c3d4e5f6...（32位小写）
```

> 验签失败抛 `HfbException`，HTTP 500。

### 1.3 两步式调用模式

**部分接口**采用"验签渲染表单 + 表单提交实际执行"两步式：

| 步骤 | 接口 | 作用 |
|---|---|---|
| Step 1 | `/Xxx`（如 `/userBind/BindAgreeUserV2`） | 商户后台 POST → 银行验签 → **返回 HTML 页面给用户** |
| Step 2 | `/XxxSave`（如 `/userBind/save`） | 用户在页面输支付密码后浏览器 POST → **真正执行资金动作** |

**纯 JSON 接口**（放款、撤标）一步式：商户后台 POST → 返回 JSON。

### 1.4 通用参数

所有接口必带：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `timestamp` | String | 是 | 毫秒时间戳 |
| `sign` | String | 是 | 见 1.2 签名规则 |

需要用户确认的接口额外必带：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `returnUrl` | String | 是 | 同步跳转 URL（用户操作完成后浏览器跳转） |
| `notifyUrl` | String | 是 | 异步通知 URL（银行主动 POST 通知商户结果） |
| `payPasswd` | String | 是 | 支付密码（6 位数字，由用户在表单中输入） |

### 1.5 异步通知机制

- 异步通知由银行端 [`ScheduledTask`](../src/main/java/com/heepay/task/ScheduledTask.java) 每秒扫描队列后发起
- **POST** 到商户提供的 `notifyUrl`，body 为 `key=value&...&sign=xxx`
- 商户响应字符串 **`success`**（小写）表示成功；否则银行重试，**最多 5 次**
- 通知参数带 `sign`，商户需验签

### 1.6 响应格式

- **两步式接口**：返回 Thymeleaf 渲染的 HTML 页面，商户后台把 HTML 响应给用户浏览器
- **JSON 接口**：返回 `application/json`

通用返回字段：

| 字段 | 说明 |
|---|---|
| `resultCode` | `0001`=成功（用户操作类），`0000`=成功（平台动作类） |
| `resultMsg` | 结果描述 |
| `timestamp` | 银行处理时间戳 |
| `sign` | 返回数据的签名，商户需验签 |

## 三、接口详情

### 1. 用户绑定（开户）— 渲染绑定页

**请求**

```
POST /userBind/BindAgreeUserV2
Content-Type: application/x-www-form-urlencoded
```

**参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `agentId` | String | 是 | 商户ID |
| `agentUserId` | String | 是 | 商户侧用户ID |
| `personalName` | String | 是 | 用户姓名 |
| `idCard` | String | 是 | 身份证号（唯一标识，已绑定则直接跳 success） |
| `bankNo` | String | 是 | 银行卡号 |
| `mobile` | String | 是 | 预留手机号 |
| `email` | String | 否 | 邮箱 |
| `returnUrl` | String | 是 | 同步跳转URL |
| `notifyUrl` | String | 是 | 异步通知URL |
| `payPasswd` | String | 是 | 支付密码 |
| `status` | String | 是 | 状态（传 "0"） |
| `timestamp` | String | 是 | 时间戳 |
| `sign` | String | 是 | 签名 |

**响应**：HTML 页面 `user/bindUser`，含用户信息表单（用户输支付密码后提交到 `/userBind/save`）。

**特殊逻辑**：若 `idCard` 已绑定过，直接返回 `user/success` 页面，不渲染绑定表单。

### 8. 投标提交

**请求**

```
POST /userInvest/invest
```

**参数**：同接口 7 全部参数

**响应**：HTML 页面 `userInvest/success`

**业务**：
1. 校验支付密码
2. 幂等校验：`agentBillNo` 在 `user_invest` 表中不能已存在
3. 检查投资人余额 ≥ 投资金额
4. 检查投资人累计投标金额 ≤ 标的总额（防超额投标）
5. `user_account.amount -= voteAmt`，`user_account.freeze_amount += voteAmt`（资金冻结）

**异步通知**：

| 字段 | 说明 |
|---|---|
| `resultCode` / `resultMsg` | `0001` / `充值成功`（注：源码文案错写） |
| `agentBillNo` | 商户订单号 |
| `agentProjectCode` | 标的编号 |
| `projectType` | `0` |
| `voteBindCode` | 投资人托管账户号 |
| `voteAmt` | 投资金额 |
| `votePrizeAmt` / `voteFeeAmt` | 奖励 / 手续费 |
| `voteNote` | 备注 |
| `timestamp` / `sign` | 通用 |

### 9. 放款（一步式 JSON 接口）

**请求**

```
POST /userInvest/AgreeAccountLendProject
Content-Type: application/x-www-form-urlencoded
```

**参数**

| 参数 | 必填 | 说明 |
|---|---|---|
| `agentProjectCode` | 是 | 标的编号 |
| `agentBillNo` | 是 | 商户订单号（**幂等键**） |
| `mchFee` | 是 | 平台手续费 |
| `timestamp` / `sign` | 是 | 通用 |

**响应**（JSON）：

```json
{
  "resultCode": "0000",
  "resultMsg": "放款成功",
  "agentProjectCode": "PROJ_1693520000000",
  "agentBillNo": "LOAN_xxx",
  "voteAmt": "5000",
  "mchFee": "0",
  "hyFee": "0"
}
```

**业务**：
1. 幂等校验：标的已放款则直接返回成功（看 `user_invest.status`）
2. 遍历该标的所有投标记录
3. 每条投资记录：解冻投资人冻结资金 + 转账给借款人
4. 扣除平台手续费（从借款人账户扣 `mchFee`）
5. 更新 `user_invest.status = 1`

> ⚠️ 已知缺陷：并发场景下幂等校验存在 TOCTOU 问题（见 Bug 报告 #6）

### 11. 还款 — 渲染确认页

**请求**

```
POST /lendReturn/AgreeUserRepayment
```

**参数**

| 参数 | 必填 | 说明 |
|---|---|---|
| `fromBindCode` | 是 | 还款人（借款人）托管账户号 |
| `agentGoodsName` | 是 | 还款商品名（描述） |
| `agentBatchNo` | 是 | 还款批次号 |
| `totalAmt` | 是 | 还款总金额 |
| `voteFeeAmt` | 是 | 商户手续费 |
| `data` | 是 | **还款明细 JSON 字符串**，见下方说明 |
| `returnUrl` / `notifyUrl` / `payPasswd` / `timestamp` / `sign` | 是 | 通用 |

**`data` 字段格式**（JSON 数组字符串）：

```json
[
  {
    "voteBillNo": "INV_xxx",
    "toBindCode": "投资人托管账户号",
    "agentProjectCode": "标的编号",
    "transitAmt": 5500.00,
    "baseAmt": 5000.00,
    "benifitAmt": 500.00,
    "feeAmt": 0.00,
    "note": "还款",
    "status": 0
  }
]
```

> ⚠️ **重要**：金额字段必须用 `BigDecimal.setScale(2)` 序列化（如 `5500.00` 而非 `5500`），否则服务端强转 `(BigDecimal)` 会抛 `ClassCastException`（见 Bug 报告 #15）

**响应**：HTML 确认页 `lendReturn/index`，展示借款人余额和还款总额。

---

### 12. 还款提交

**请求**

```
POST /lendReturn/returnCommit
```

**参数**：同接口 11 全部参数

**响应**：HTML 页面 `lendReturn/success`

**业务**：
1. 校验支付密码
2. 校验：还款总额 = 各明细 `transitAmt` 之和
3. 校验：每条明细 `transitAmt = baseAmt + benifitAmt`
4. 借款人扣款 `totalAmt`
5. 遍历还款明细，按 `toBindCode` 给每个投资人转账 `transitAmt`
6. 写 `user_return` + `user_item_return` 表

> ⚠️ 已知缺陷：金额校验用 `double` 比较，浮点精度问题可能导致正常还款被判定金额不符（见 Bug 报告 #12）

**异步通知**：由服务端组装，含还款结果及各明细处理状态。

### 4.1 标的投满放款流程

```
投资人                      旺旺信贷(商户)                 旺旺银行(本项目)
  │                              │                              │
  │ 1.注册                       │                              │
  │ ───────────────────────────►│                              │
  │                              │ 2.POST /userBind/BindAgreeUserV2
  │                              │ ────────────────────────────►│ 验签
  │                              │ ◄────────────────────────────│ 返回绑定页HTML
  │ 3.输支付密码                  │                              │
  │                              │ 4.POST /userBind/save        │
  │                              │ ────────────────────────────►│ 建账户
  │                              │ ◄────────────────────────────│ 异步通知bindCode
  │                              │                              │
  │ 5.充值                       │                              │
  │                              │ 6.POST /userAccount/AgreeBankCharge + /recharge
  │                              │ ────────────────────────────►│ 余额+10000
  │                              │                              │
  │ 7.投标                       │                              │
  │                              │ 8.POST /userInvest/AgreeUserVoteProject + /invest
  │                              │ ────────────────────────────►│ 冻结5000
  │                              │                              │
  │                              │ 9.标的投满,放款              │
  │                              │ 10.POST /userInvest/AgreeAccountLendProject
  │                              │ ────────────────────────────►│ 解冻+转账给借款人
  │                              │ ◄────────────────────────────│ JSON 返回放款成功
  │                              │                              │
  │                              │ 11.到期,借款人还款           │
  │                              │ 12.POST /lendReturn/AgreeUserRepayment + /returnCommit
  │                              │ ────────────────────────────►│ 借款人扣款,投资人收款
```

### 4.2 幂等键说明

| 接口 | 幂等键 | 作用 |
|---|---|---|
| 充值 | `agentBillNo` | 防重复充值 |
| 提现 | `agentBillNo` | 防重复提现 |
| 投标 | `agentBillNo` | 防重复投标 |
| 放款 | `agentProjectCode` + status | 防重复放款 |
| 还款 | `agentBatchNo` | 防重复还款 |

> ⚠️ 充值/提现/还款的幂等校验**未在代码中实现**，仅投标和放款有实现（见 Bug 报告 #8）

## 五、错误处理

### 5.1 验签失败
```
HTTP 500
抛出 HfbException(SIGN_ERROR)
```

### 5.2 支付密码错误
```
HTTP 500
抛出 HfbException(PASSWORD_ERROR)
```

### 5.3 业务异常
余额不足、标的已放款、投标超额等场景，均抛 `HfbException`，HTTP 500，异常消息见 [`ResultCodeEnum`](../src/main/java/com/heepay/util/ResultCodeEnum.java)。
